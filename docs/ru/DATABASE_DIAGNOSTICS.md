# Диагностика MySQL, MariaDB и PostgreSQL

## Что это

Диагностика СУБД дополняет обычный мониторинг Linux-сервера. Pinguva показывает
подключения, активные запросы, длительность, ожидания, блокировки, технические
группы запросов и короткие инциденты нагрузки.

Функция доступна на тарифе Enterprise и требует Pinguva Agent `0.2.13` или
новее.

## Подключение

1. Установите или обновите Linux-агент на сервере базы данных.
2. Откройте `Интеграции и API` -> `Диагностика СУБД`.
3. Выберите сервер и тип базы. Обычно достаточно `Определить автоматически`.
4. Запустите показанную Pinguva команду на выбранном сервере через `sudo`.
5. Через одну-две минуты откройте карточку сервера.

Если на сервере уже настроена интеграция Bitrix24, отдельное подключение СУБД
не требуется и блокируется. MySQL или MariaDB продолжает контролироваться через
Bitrix24.

## Доступ к MySQL и MariaDB

Агент сначала использует `/root/.my.cnf`, только если это обычный файл
`root:root` с правами `0600`. Содержимое файла и пароль не передаются в Pinguva
и не выводятся в журнал. Если безопасного файла нет, агент пробует локальный
Unix socket.

Проверка файла без просмотра содержимого:

```bash
sudo stat -c '%a %U:%G %F' /root/.my.cnf
```

## Доступ к PostgreSQL

Агент выполняет фиксированные read-only запросы к системным представлениям
PostgreSQL. Расширение `pg_stat_statements` используется только если оно уже
установлено. Агент не включает расширение и не изменяет PostgreSQL.

## Безопасная проверка

```bash
sudo systemctl start pinguva-database-diagnostics.service
sudo journalctl -u pinguva-database-diagnostics.service -n 50 --no-pager
```

Для PostgreSQL дополнительно:

```bash
sudo -u postgres psql -Atc "SELECT version();"
```

## Какие данные не передаются

- пароли и содержимое файлов учётных данных;
- исходный SQL и параметры запросов;
- значения из таблиц;
- полные grants и конфигурационные файлы;
- произвольные журналы сервера.

Если безопасно получить расширенную группу запросов нельзя, Pinguva показывает
только базовые показатели и честно отмечает недоступный источник.

## Отключение

Отключите интеграцию в карточке сервера и выполните выданную команду:

```bash
sudo pinguva-agent database disable
```

Основной агент и история до окончания срока хранения не удаляются.
