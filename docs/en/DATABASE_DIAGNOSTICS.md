# MySQL, MariaDB and PostgreSQL Diagnostics

## Overview

Database diagnostics extend regular Linux server monitoring. Pinguva displays
connections, active queries, duration, waits, locks, technical query groups and
short load incidents.

The feature requires an Enterprise workspace and Pinguva Agent `0.2.13` or
newer.

## Setup

1. Install or update the Linux agent on the database server.
2. Open `Integrations and API` -> `Database diagnostics`.
3. Select the server and database type. `Automatic detection` is suitable for
   most installations.
4. Run the command generated by Pinguva on that server through `sudo`.
5. Open the server details after one or two minutes.

If Bitrix24 is already configured on the server, a separate database
integration is not required and is blocked. MySQL or MariaDB remains monitored
through the Bitrix24 diagnostics connector.

## MySQL and MariaDB access

The agent uses `/root/.my.cnf` only when it is a regular `root:root` file with
`0600` permissions. File contents and passwords are neither sent to Pinguva nor
written to logs. Without a safe file, the agent attempts a local Unix socket.

Check metadata without displaying the file:

```bash
sudo stat -c '%a %U:%G %F' /root/.my.cnf
```

## PostgreSQL access

The agent runs fixed read-only queries against PostgreSQL system views.
`pg_stat_statements` is used only when already installed. The agent does not
install extensions or change PostgreSQL configuration.

## Safe verification

```bash
sudo systemctl start pinguva-database-diagnostics.service
sudo journalctl -u pinguva-database-diagnostics.service -n 50 --no-pager
```

For PostgreSQL, you can also run:

```bash
sudo -u postgres psql -Atc "SELECT version();"
```

## Data that is not transmitted

- passwords or credential-file contents;
- source SQL or query parameters;
- table values;
- full grants or configuration files;
- arbitrary server logs.

When an extended query source is unavailable, Pinguva keeps base diagnostics
active and identifies the unavailable source.

## Disable

Disable the integration in the server card and run the generated command:

```bash
sudo pinguva-agent database disable
```

The main agent and retained historical data are not deleted.
